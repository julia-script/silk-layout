# Standards and reference policy

## Authority

The normative algorithm wins over a browser observation. A Chrome mismatch is evidence to investigate, not permission to change a specification-derived expectation. An expressly permitted algorithm choice is not a conformance failure; the flex intrinsic-size implementation selects the web-compatible algorithm in Flexbox §9.9.1.2.

The reference baseline is `specs.lock.json`: 62 complete documents, original/resolved URLs and SHA-256 hashes. `python3 scripts/fetch-specs.py` fetches missing documents and verifies cached bytes under `.cache/specs/`. Changed upstream bytes fail verification. `--update` is an explicit standards-baseline change, not a routine build step. `--only NAME` selects references (repeatable); with `--update`, it preserves all unselected lock records. Draft URLs are mutable; retain the verified local cache when an upstream draft changes. Downloaded documents retain their original licenses and are not part of the MIT library distribution. The Unicode annex revisions match the pinned CSS Text/Writing Modes bibliographies. Adding Unicode, the first-formatted-line dependency and Break 4 did not refresh the existing CSS snapshots.

Use [CSS 2.1](https://www.w3.org/TR/2011/REC-CSS2-20110607/) and its errata for foundational block rules, including margin collapse and floats. CSS 2.2 is a Working Draft reference, not a blanket replacement Recommendation. Later modules override the portions they explicitly replace. The initial CSSWG drafts identify source revision `33d168d9c3bfd7bda4babaa208edfd13c82fbb52`; the separately added [Pseudo-Elements 4 first-formatted-line definition](https://drafts.csswg.org/css-pseudo-4/#first-formatted-line) identifies `1da0d9fb61d62f53e893b58f85bd109f0c8b9321`.

These references define the target, not a claim that every feature of the referenced modules is implemented. The identified block/flex audits cover host-supplied fragmentation, outer float break boundaries, margin adjacency, phantom-line geometry, scrolling, orthogonal/baseline interactions, and bidi static-position/source geometry. Reproduced defects have regression coverage; underspecified or approximation-permitting cases use the explicit policies below. Composable source-text breaking/shaping and justification measurement use a separate replaceable service; the CLI exercises only a bounded ASCII/Bidi_Control horizontal profile, not a complete Unicode/font backend. Full conformance must not be inferred from the focused regression corpus.

The 947 existing non-subgrid fixture outputs also remain byte-identical. This establishes unchanged behavior, not correctness of every existing baseline policy.

Geometry uses the engine's `f32` representation. General overflow unions discard rectangles with either extent below 1/64px; the Grid track-extent path still permits a zero-sized opposite axis. This precision policy can omit real narrow overflow and is not exact real-arithmetic propagation. Browser geometry comparisons retain their 0.05px tolerance; the `f32` migration changes last-bit values in earlier diagnostic measurements without changing their specification choices.

The engine accepts `grid`, `block grid`, `inline-grid`, and `inline grid`, builds grid containers and blockified items, and retains Tree-owned structured track templates, interned names, areas and placement values. [Grid §6](https://drafts.csswg.org/css-grid-2/#grid-items) supplies anonymous items for contiguous non-whitespace text; whitespace-only sequences generate no item. `contents` is flattened, `none` suppresses its subtree, floats on items do not float, and item margins remain separate under [§6.4](https://drafts.csswg.org/css-grid-2/#item-margins). Unlike flex collapse struts, `visibility:collapse` leaves grid occupancy intact.

**Explicit numeric placement and track sizing are implemented.** Positive/negative integer lines, numeric spans and reversed/equal endpoint handling follow [§8.3](https://drafts.csswg.org/css-grid-2/#line-placement). Fixed tracks, percentages, `fr`, and gaps define item areas. `start`, `end`, `center` and `stretch` self-alignment use those areas as available space and percentage bases under [§6.2](https://drafts.csswg.org/css-grid-2/#grid-item-sizing). Logical placement covers horizontal, vertical and RTL axes.

Implicit tracks and cyclic `grid-auto-rows`/`grid-auto-columns` lists follow [§§7.5–7.7](https://drafts.csswg.org/css-grid-2/#implicit-grids), including backwards cycling before the explicit grid. [§8.5](https://drafts.csswg.org/css-grid-2/#auto-placement-algo) places definite items, major-axis-locked items, then automatic items in stable order-modified document order. Row and column flow share one logical-axis algorithm; sparse retains cursor history and dense searches again from the implicit-grid start.

Named lines, positive/negative named occurrences, named spans and implicit fallback lines follow [§8.3](https://drafts.csswg.org/css-grid-2/#line-placement). Bare names prefer the corresponding `-start`/`-end` alias; integer-plus-name values count exact names instead. [§7.3](https://drafts.csswg.org/css-grid-2/#grid-template-areas-property) supplies area-defined explicit extents and implicit line names, merged with authored names. Explicit suffixed names also create implicit area aliases. Placement uses integer IDs after a retained preparation index sorts and deduplicates line occurrences.

[§7.2.3](https://drafts.csswg.org/css-grid-2/#repeat-notation) expands integer repeats and counts complete automatic patterns against a definite preferred size, else maximum, else minimum; minimum-only counting rounds upward. Counting floors track sizes to 1px and checks actual extents at fractional boundaries rather than adding an epsilon. Empty `auto-fit` tracks become fixed zero tracks after placement; [§11.1](https://drafts.csswg.org/css-grid-2/#collapsed-gutter) makes interior gutters coincide and removes leading/trailing gutters. Area-defined but unsized explicit tracks retain `grid-auto-*` pattern sizing.

A definite min/max constraint is not a percentage-track basis. Following the accepted clarification in [CSSWG #4480](https://github.com/w3c/csswg-drafts/issues/4480), counting uses only definite track functions; if neither function is definite, it repeats once. Cyclic percentage gaps contribute zero during intrinsic counting, preserving any fixed `calc()` component, then resolve for layout under [Gaps §2.3](https://drafts.csswg.org/css-gaps-1/#gap-percent).

[§§12.3–12.8](https://drafts.csswg.org/css-grid-2/#algo-track-sizing) cover intrinsic keywords, `minmax()`, `fit-content()`, increasing span groups, planned increases, infinitely-growable limits, maximization, definite/indefinite flex fractions and automatic-track stretch. Item contributions use [§6.6](https://drafts.csswg.org/css-grid-2/#min-size-auto), including the track-dependent automatic minimum, scrollable overflow, fixed-track caps, and the replaced/non-replaced aspect-ratio distinction. [§5.2](https://drafts.csswg.org/css-grid-2/#intrinsic-sizes) drives container min/max-content sizes in both axes. Orthogonal items and percentage-dependent contributions use the column-then-row order and bounded cross-axis adjustment in [§12.1](https://drafts.csswg.org/css-grid-2/#algo-grid-sizing). Cyclic track/gap percentages resolve against zero for intrinsic sizing, then against the established content size for layout without enlarging it to absorb overflow.

In [§12.5.1](https://drafts.csswg.org/css-grid-2/#extra-space), increases allocated to non-affected tracks are retained even though the later planned-increase wording names affected tracks. This follows the accepted intent of [CSSWG #3648](https://github.com/w3c/csswg-drafts/issues/3648): exhaust available capacity in other spanned tracks before exceeding the intrinsic tracks' growth limits, rather than discarding that allocation.

For §8.5 step 2, “smallest positive index” is interpreted over the implicit grid, not authored line numbers relative to explicit line 1. Sparse history is keyed by the definite row-start position, while occupancy covers every spanned row. [CSSWG #14687](https://github.com/w3c/csswg-drafts/issues/14687) requests clarification of both phrases. These choices agree with the executed Chrome and Taffy diagnostics; they are explicit interpretations, not a claim that the wording is unambiguous.

[§11.5](https://drafts.csswg.org/css-grid-2/#grid-align) distributes the sized tracks, including space-between/around/evenly and safe/unsafe positional alignment. Collapsed tracks do not receive distribution spaces. Distributed gutters participate in spanning areas before dependent-axis contribution probes. [§11.2](https://drafts.csswg.org/css-grid-2/#auto-margins) resolves item auto margins before self-alignment: positive free space is absorbed, while overflowing items resolve auto margins to zero and still use their box-alignment properties. Logical self-start/end, physical left/right, and the `normal` distinction for replaced/aspect-ratio items use the container and item writing modes separately.

Baseline self-alignment follows [Grid §11.3](https://drafts.csswg.org/css-grid-2/#row-align) and [Align 3 §9](https://drafts.csswg.org/css-align-3/#baseline-rules). Eligibility is frozen before track sizing, distinguishing authored definite sizes from content-derived used sizes and treating indefinite flexible tracks as intrinsic. Independent minimum, min-content and max-content baseline samples produce contribution shims; fixed-track members remain in their sharing groups. Final group placement uses safe physical fallbacks, the context's dominant baseline type, and font-table mirrors for opposite line orientations. [Grid §11.6](https://drafts.csswg.org/css-grid-2/#grid-baselines) exports first/last baselines by sharing-group and grid-order priorities, including spanning items and empty containers.

For default overflow alignment, the engine selects the explicitly permitted unsafe behavior in [Align 3 §4.4.1.3](https://drafts.csswg.org/css-align-3/#auto-safety-default); optional ancestor-dependent “smart” safety is not implemented. Explicit `safe` still falls back to start when its alignment subject overflows.

[Grid §5.3](https://drafts.csswg.org/css-grid-2/#overflow) includes the aligned grid rectangle itself in scrollable overflow, even when tracks are empty or items are smaller than their areas. The shared overflow hook preserves zero extent in the other axis and includes scroll-container padding without changing generic block/flex rectangle handling. [Align §5.3](https://drafts.csswg.org/css-align-3/#overflow-scroll-position) opens otherwise unreachable overflow only as far as the alignment subject requires; unrelated absolute descendants cannot extend that start-side boundary. Inline distribution reads `justify-content`, block distribution reads `align-content`, and explicit safe fallback does not open the origin.

CSS grid shorthands/token parsing are not accepted. The implementation limit is 10,000 tracks per axis ([§5.4](https://drafts.csswg.org/css-grid-2/#overlarge-grids)); integer-repeat expansion must fit that bound, automatic repetition counts are capped to complete patterns within it, and placement line magnitudes/spans are clamped to it. Automatic searches terminate at that bound and clamp overflowing placements to boundary tracks.

Subgrid follows [§9](https://drafts.csswg.org/css-grid-2/#subgrids): either or both axes inherit the used parent span, mapped into the child's writing mode and direction. Explicit line names remain separate from area-generated aliases; each descendant clips inherited areas and regenerates their edge names, retaining only the relevant axis across independent-axis boundaries. Local name groups and fixed/auto-fill name repeats participate in automatic spans. Hypothetical placement resolves before inherited-axis clamping; those axes never gain implicit tracks. A subgrid outside an eligible in-flow parent Grid falls back to `none`.

[§12.1](https://drafts.csswg.org/css-grid-2/#algo-overview) contributions traverse the connected inherited physical axis separately from direct-item placement/final output. Descendants contribute to the owning tracks; subgrid wrappers contribute accumulated edge margins, borders, padding and scrollbar gutters, not their own inherited-axis size constraints. Gap differences telescope through nested subgrids, and hypothetical edge items account for unoccupied edge tracks. Baseline groups cross subgrid boundaries. Inherited axes stretch regardless of authored preferred/min/max sizes or self/content alignment; standalone axes retain ordinary Grid sizing.

`normal` gaps have a distinct computed representation and are not aliases for explicit zero. Subgrid requests carry an immutable, stage-specific inherited-context identity in the existing size/final cache key. Placement preparation keys that identity too, so equal total area does not alias changed tracks, names, gaps or clipped areas. A between-compute tracing barrier reclaims unreferenced descriptors; checkpoint rollback retains descriptors referenced by surviving probe requests. Accepted geometry journals and fragment full-box metadata retain the chosen context, including positioning-only continuation reconstruction from the current parent frame. No `Layout` or measurement-provider fields were added.

Absolute containing areas follow [§10.1](https://drafts.csswg.org/css-grid-2/#abspos-items), including existing implicit lines, names, spans, area aliases, automatic repetition and distributed track positions. [§8.3.1](https://drafts.csswg.org/css-grid-2/#grid-placement-errors) conflicts resolve before nonexistent endpoints become auto; absolute placement never generates tracks. Insets, dimensions and percentage margins use each child's area, not a sibling's cached rectangle. [§10.2](https://drafts.csswg.org/css-grid-2/#static-position), refined by [Position 3 §3.5.3](https://drafts.csswg.org/css-position-3/#static-position-rect), uses the grid parent's content rectangle for static positioning unless that same parent establishes the actual containing block, in which case it uses the resolved area. Static auto margins are zero; self-alignment inherits items alignment only for the static position. Fixed positioning retains its initial containing block.

Auto lines use the scrollable padding boundary on scrollable axes. [Position 4 §2](https://drafts.csswg.org/css-position-4/#scrollable-containing-block) excludes absolute descendants, descendant-content overflow and relative offsets from that boundary. Final snapshots retain track edge pairs, integer name occurrences and one clipped normal-flow padding rectangle. The engine's existing per-source overflow calculation supplies that rectangle; clipping a previously combined union would incorrectly let wholly unreachable boxes enlarge the other axis. Final positioned grids and effective subgrids publish accepted geometry; it survives retained computes/remapping and participates in speculative checkpoint rollback without adding fields to or copying `Layout`.

Twenty-two original native cases cover resolver/projection boundaries, retained lifecycle, sibling areas, placement/template edits, remapping, mode transitions and fixed grids on differently sized pages. Thirty-one hand-derived specification scenes exercise the positioned CLI path; 28 agree with Chrome 155 and three retain the normative differences recorded below. Position 3 source revision `8c141afe47996f98bcfacf26c6771f183540d70e` predates the existing lock; its grid static-position refinement is not a standards-baseline update.

Grid fragmentation implements row-boundary breaks and item `break-before`/`break-after` propagation under [Grid §13](https://drafts.csswg.org/css-grid-2/#pagination). First/last occupied-edge controls propagate to the container; an internal forced break in one item does not force its parallel siblings. Spanning items resume independently of row reservations. Gutters disappear across breaks, while distributed alignment space retains fractional progress. Baseline export considers only items published in the current fragment. Grid no longer has a blanket monolithic policy; the ordinary replaced, orthogonal, scroll/clipping and other Break 3 monolithic rules still apply.

Grid §13 deliberately leaves the exact fragmented layout undefined. The implementation uses continuous track sizing followed by row reservation and independent item fragmentation, with growth for intrinsic-minimum rows and indefinite flexible rows as suggested by the non-normative [§13.1 sample algorithm](https://drafts.csswg.org/css-grid-2/#fragmentation-alg). Row-spanning items do not trigger that row-growth decision. Accepted automatic-repeat counts remain fixed across a fragmented compute so varying page inline sizes do not move already-placed items to different rows; track sizes still adapt to each actual frame. This repeat-count choice is an engine policy, not a uniquely mandated Grid algorithm.

Fragmented positioned grids retain each accepted fragment's inline track geometry and the continuous row-line positions after breaks. Absolute area percentages and static alignment use the current page's columns, including when later pages have different inline sizes. Positioning-only continuations obtain fresh allocation from a checkpointed Grid probe, retaining its pooled geometry while discarding speculative layouts and publications. Joined containing areas use the first frame-start and final frame-end decoration edges; this also applies when the grid and fragmentainers have opposite parallel block directions.

Grid probes and final layout share item placement across retained computes, keyed by box identity, inherited-context identity and both resolved automatic repetition counts. A changed count or inherited context rebuilds expanded names, placement and auto-fit occupancy. `LayoutCache.gridMemos` owns the existing pooled item/track buffers and sparse-row occupancy bitmaps; `clearBox` invalidates a changed container and `remap` clears identities without discarding capacity. Only occupied rows receive bitmap words, and fully definite grids do not build occupancy. Expanded-template storage is lazy; ordinary numeric grids borrow authored tracks without copying them. Placement and sizing scratch share an owned lease, so retaining placement adds no list copies or second scratch allocation. Track sizes are recomputed for each request. Fragmented computes still invalidate retained results, but preserve their scratch capacity.

Original native regressions exercise viewport changes within and across an automatic-repeat count boundary, then order changes, hide/show box renumbering and template replacement. They assert hand-derived item rectangles rather than cache implementation details.

Grid contribution probes reuse their scalar result when the block-axis min-content and max-content requests are identical; they do not rebuild and search an identical size-cache key. Width probes use the engine's axis-only request contract, retaining full-size requests for aspect ratios and natural dimensions. Contribution and item-area constraints use the existing zero-edge resolution shortcut rather than resolving known-zero edges repeatedly. The hot track-policy scan is inlined to expose unused policy fields to the compiler at each caller.

Cross-axis change checks defer otherwise-unused maximum contributions until a changed minimum or min-content contribution triggers track re-sizing. Intrinsic authored constraints and baseline groups still obtain the maxima they require. Native cases distinguish a changed min-content contribution, which must re-size using the new maximum, from a maximum-only change, which must not trigger another sizing pass.

Fixed-minimum tracks with fixed maxima, or flexible maxima under definite used space, omit unused item contributions ([§12.5](https://drafts.csswg.org/css-grid-2/#algo-content), [§12.7](https://drafts.csswg.org/css-grid-2/#algo-flex-tracks)). Indefinite flexible tracks and intrinsic minima retain collection; item minimum overflow and final baseline alignment remain independent.

Internal sizing requests carry border-box minimum bounds separately from known sizes. A bound preserves larger natural sizes, wins over a smaller maximum, does not inherit to children, and does not establish percentage definiteness. Intrinsic queries ignore the bound in their queried axis; cross-axis bounds remain live, including for opaque measurement and shrink-to-fit queries. Cache keys distinguish effective bounds, and fragmented containing-block reconstruction retains them without adding fields to `Layout`. Authored intrinsic minimum keywords cannot overwrite a stronger request bound.

Size-cache matching rejects different available constraints and known sizes before checking shared context. It still distinguishes effective minimum bounds and every existing context field; baseline and full-size capabilities remain directional. Fresh plain measured-leaf probes use the existing complete leaf-layout path directly, retaining baselines, overflow, opaque cross-axis dependencies and min/max remeasurement. Fragmented or otherwise ineligible probes retain the general dispatch.

Fragmented container-item allocations use a shared Flex/Grid parent probe when reconstructing a later-page containing block. The probe requests final item allocation and placement, retains complete `Layout` results, and rolls back speculative publication and scalar layouts. Allocated auto extents and leading alignment have separate fractional progress; Grid row progress, handled boundaries, consumed flow and accepted automatic-repeat counts belong to the existing rollback-journaled continuation store, not the placement memo cache. These internal contracts add no fields to `Layout` or the measurement-provider API.

Grid supplies automatic item minimums through those bounds when an axis has no known size, instead of running a separate preliminary layout to discover whether the minimum binds. Known axes retain their direct lower-bound clamp. Track-sizing contribution probes are retained; the normal sizing loop enforces a binding floor while preserving larger natural sizes and definite preferred cross sizes.

Baseline scratch is allocated only for containers requesting baseline self-alignment. Retained per-item samples and sparse used-track sharing groups avoid allocating a full group record for every possible track. Ordinary final placement still uses `layoutNode` and `LayoutPass.place`; neither baseline alignment nor track distribution adds fields to `Layout` or copies its record.

Empty grid containers retain distinct min-content and max-content probe constraints. Their track definitions can supply different intrinsic sizes even without children ([Grid §5.2](https://drafts.csswg.org/css-grid-2/#intrinsic-sizes)); the ordinary empty-box cache-key shortcut must not erase that distinction.

A reused final subtree may still depend on intrinsic probes older than the previous compute. Early-cutoff validation rejects candidates with such probes instead of silently omitting those dependencies. Otherwise, a retained viewport-only compute followed by a text edit can leave content-sized grid tracks stale even when the item's previous final box still fits the edited text.

Full-width grouped interruption geometry follows Chrome where [CSSWG #13711](https://github.com/w3c/csswg-drafts/issues/13711) and [#14104](https://github.com/w3c/csswg-drafts/issues/14104) remain unresolved. Phantom continuations owning an empty inline, float or positioned anchor retain nonpainting inline-axis geometry without adding line height. Inline-owned floats establish the required continuation even after a lifted block. Visual ordering derives line participation from each item's own edges, not an ancestor's cloned edges. The three initial compatibility probes now match Chrome; five of six additional RTL/embedding probes match. The remaining embedding difference retains [CSS2 §10.3.7 rule 2](https://www.w3.org/TR/CSS22/visudet.html#abs-non-replaced-width): the static-position containing block selects the static edge, not the embedded inline's direction. Pinned CSSOM union rules and Position 3 content-edge/end-most containing geometry likewise take precedence over Chrome's degenerate bounds and absolute widths.

Scroll requests are clamped against final reachable overflow and the gutter-adjusted padding box before visual positioning. Focused native CLI and Chrome runs agree on oversized positive/negative requests, RTL and vertical-rl reverse ranges, non-overflowing content, viewport bounds, and fixed-position independence. The engine preserves reachable alignment overflow rather than imposing a positive-only range; existing reverse-flex and centered/end-alignment fixtures remain passing. See [CSSOM View element scrolling](https://drafts.csswg.org/cssom-view/#scroll-an-element) and [Align 3 alignment overflow](https://drafts.csswg.org/css-align-3/#overflow-scroll-position).

Explicit `baseline-source:first/last` preserves a block-axis scroller's content baseline; only `auto` receives the legacy block-end baseline under [Align 3 §9.1](https://drafts.csswg.org/css-align-3/#baseline-export). Border clamping remains applicable. Original native/Chrome probes agree on auto/first/last selection and a scrolled-content case: the last baseline remains 8px with a 15px scroll offset, aligning a 5px peer at y=3px while the scrolled content moves independently.

Sticky offsets consume the clamped scroll state. The pinned Position 3 text still defines a margin-based position box; the resolution in [CSSWG #9052](https://github.com/w3c/csswg-drafts/issues/9052) to ignore margins has not been applied to that text. This implementation interprets “distance” as nonnegative geometric separation, retains negative used margins, and uses each box's own pre-collapse margin with its post-collapse normal placement. Collapsed-edge ownership and signed-versus-unsigned distance remain textual ambiguities.

For sticky containment whose containing block is itself scrollable in the affected axis, this implementation follows Chrome's full scrolling-content extent, including positioned and descendant overflow; the viewport boundary follows the same rule. [CSSWG #2609](https://github.com/w3c/csswg-drafts/issues/2609) records the ambiguity in Position 3. Position 4's distinct normal-flow scrollable-containing-block definition currently addresses absolute positioning and is not silently substituted here. The `sticky-scrolling-cb-*` Chrome fixtures guard this compatibility choice, including containing-block end limits. Explicit pinned scrollport-inset and margin rules still take precedence over Chrome.

Overflow 3 §3.3 leaves inclusion of non-flex margin areas discretionary. The selected policy includes positive declared margins and resolved auto margins for in-flow/float boxes, without treating CSS2 inline overconstraint corrections as additional margin content. This does not change `Layout.usedMargin`. Relative positioning retains normal overflow extent and can enlarge it. Align 3 §5.3 relaxes unreachable-region clipping only enough to expose the overflowing alignment subject, not arbitrary positioned overflow beyond it.

[Overflow 3 §5.1](https://drafts.csswg.org/css-overflow-3/#scrollbar-sizing) requires starting without automatic scrollbars and recalculating when necessary. This implementation adds selections monotonically within one compute and resets them on the next call. Chrome retains a selected vertical bar in the observed intrinsic feedback case `width:max-content; aspect-ratio:1; overflow:auto` with 100×110px content: the resulting 115×115px box no longer overflows vertically but keeps the 15px gutter. The `scrollbar-intrinsic-ratio-cycle` Chrome fixture guards that compatibility choice; the draft does not specify a complete scrollbar-cycle resolution algorithm.

Scrollbar dimensions, overlay/classic choice and physical sides are host-defined under [Overflow 3 §5.2](https://drafts.csswg.org/css-overflow-3/#scrollbar-gutter-property). The replaceable measurement service supplies them. The fixture service's definite-space and mirrored-pair clamping are explicit synthetic-UA policies, not normative CSS dimensions. Chrome comparisons validate the actual policy through content-box quads and retain unsupported results when Chrome cannot represent it.

Flex shrinking uses the allotted inner flex base before subtracting gutters from final content geometry. Intrinsic bases already include scrollbar contributions from intrinsic sizing. The pinned modules do not separately specify scrollbar treatment in scaled shrink weights; this sizing-input/used-content distinction follows the observed Chrome behavior. Two 100px bases in a 150px row shrink to 75px each even when only one item reserves a 15px gutter. With intrinsic bases 65px and 50px in a 100px row, their targets are approximately 56.522px and 43.478px. The `scrollbar-scaled-shrink-*` Chrome fixtures guard both cases.
